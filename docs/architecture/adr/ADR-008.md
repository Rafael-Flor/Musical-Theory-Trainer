# ADR-008 — Utilização de eventos para comunicação ente módulos

**Data:** 01/10/2026 

**Estado:** Aceite 

**Decisor:** Rafael Flor

---

## Contexto

A aplicação em desenvolvimento é constituída por vários módulos responsáveis por funcionalidades distintas, sendo necessário estabelecer mecanismos de comunicação entre estes para permitir funcionamento da aplicação. Adicionalmente, a comunicação entre módulos deve facilitar situações em que determinadas ações realizadas num módulo podem desencadear ações noutro módulo. 
A solução adotada, para este efeito, pode influenciar o acoplamento entre os módulos e as dependências existentes entre os mesmos. 

---

## Decisão

Foi decidido utilizar um sistema simples de eventos para permitir comunicação entre os diferentes módulos da aplicação, particularmente entre os módulos que se situam na fronteira de responsabilidades aplicaionais.

---

## Alternativas consideradas


| Alternativa | Razão de rejeição |
|------------|------------------|
| Comunicação direta entre módulos | Esta abordagem é adequada para a comunicação entre componentes que pertencem à mesma área de responsabilidade. No entanto, em situações como a comunicação da interface gráfica com o gestor de exercícios, criaria dependências diretas entre módulos com responsabilidades distntas, aumentando o  acoplamento entre os mesmos. |
| Uso do sistema de sinais do PySide6 | O PySide6 disponibiliza um sistema de sinais que permite realizar a comunicação baseada em eventos. No entanto, a sua utilização em módulos que não dependem da interface gráfica introduziria uma dependencia adicional do PySide6 nesses módulos. |

---

## Consequências

**Positivas:**
- Redução das dependências nos módulos, todos os módulos que precisem de utilizar eventos podem importar uma simples classe de eventos que é escrita em Python, evitando dependências de outras bibliotecas.
- Redução do acoplamento, ao evitar comunicação direta os módulos não precisam de conhecer os outros módulos com quem comunicam.
- Ações realizadas num módulo, como interação do utilizador, podem facilmente desencadear ações noutro módulo

**Negativas / trade-offs:**
- Implica a consequente conexão dos eventos às ações a tomar
