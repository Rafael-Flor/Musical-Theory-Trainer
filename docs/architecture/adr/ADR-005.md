# ADR-005 — Implementação do Modelo de Teoria Musical em código Python

**Data:** 04/09/2026  

**Estado:** Proposto 

**Decisores:** Rafael Flor

---

## Contexto

Um dos requisitos da aplicação é a geração automática de exercícios de teoria musical. 
Para permitir a geração procedural de exercícios é necessário um modelo de teoria musical que contenha descrições genéricas e estáticas de conceitos musicais, como escalas, acordes ou progressões harmónicas. 
O modo como o modelo de teoria musical será implementado poderá ter consequências no modo como os dados são acedidos, na complexidade do código e nos recursos utilizados pela aplicação.

---

## Decisão

Optou-se por implementar o Modelo de Teoria Musical diretamente em código Python através de um módulo dedicado.

---

## Alternativas consideradas



| Alternativa | Razão de rejeição |
|------------|------------------|
| Ficheiros externos |Esta alternativa permitiria separar os dados da implementação. No entanto, uma vez que os dados terão uma dimensão reduzida, sem necessidade de edição por utilizadores ou sistemas externos, não se considera que esta vantagem seja relevante para a aplicação em causa. Por outro lado, utilizando uma implementação direta em código será possível evitar operações de leitura e processamento dos dados, reduzindo a complexidade da implementação associada à gestão de ficheiros.|
| Bases de dados | Não se considera esta alternativa adequada aos requisitos da aplicação, visto que os dados que o modelo irá guardar serão relativamente reduzidos e estáticos. Adicionalmente, considera-se que a gama de funcionalidades que os sistemas de bases de dados oferecem, seria pouco útil para o que a aplicação requer. Assim sendo, não se considera esta solução adequada uma vez que, para além de não trazer vantagem significativa, haveria um aumento da complexidade associado à comunicação com um sistema externo de base de dados.  |

---

## Consequências

**Positivas:**
- Acesso direto aos dados, sem necessidade de operações de leitura ou comunicação com sistemas externos
- Menor complexidade de implementação

**Negativas / trade-offs:**
- Manutenção do modelo ligada à manutenção de código
